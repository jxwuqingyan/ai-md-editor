# Markdown 编辑器产品 Review 与简化优化方案

> 审查日期：2026-11-14  
> 审查目标：面向 Markdown 文字工作者的日常写作，保留最常用、最核心的能力，让操作直接、可靠、容易学。  
> 审查方式：静态阅读项目协作约定、README、产品/交互方案、应用主进程、渲染界面、编辑器封装、共享逻辑与测试说明；本次没有运行应用或测试。  
> 范围说明：仓库当前有未提交的代码改动，本报告是基于审查时工作区的检查建议，合并这些改动后需再按相关验收项复核。  
> 后续决策：0.14.25～0.14.27 按使用者要求把有序列表、表格、公式、任务列表、警告框等入口平铺到底部工具栏，并从原生菜单移除重复项；本报告「主工具栏收敛到 6–8 个」的建议未被采纳，仅作历史评审记录保留，实际界面以 README 与 CHANGELOG 为准。

## 1. 结论

项目已经不是“功能不够”的阶段。文件和标签管理、所见即所得与源码切换、常用 Markdown 排版、表格、任务列表、查找替换、文件夹搜索、大纲、图片、公式、图表、导出和跨平台快捷键等能力都已覆盖。

当前最值得投入的是三件事：**保护用户文稿、让 Markdown 往返编辑可靠、降低日常界面的操作负担**。继续增加高级语法、菜单项和格式按钮，收益会低于把保存/冲突处理做扎实，以及把不常用功能从主写作路径里收起来。

建议产品体验收敛为：打开或新建文档 → 写作与常用格式 → 查找和导航 → 图片/链接等内容管理 → 保存、预览与导出。常用操作始终容易找到，高级能力需要时再展开。

## 2. 项目已有的核心能力

以下能力已经存在，建议以打磨与验收为主，不重复建设：

- 本地文件打开、保存、另存为、自动保存、多标签和最近文档。
- 所见即所得编辑与源码模式切换，标题、段落、粗体、斜体、列表、引用、代码、链接、图片、表格等常见写作结构。
- 撤销重做、文档内查找替换、目录导航、文件夹内容搜索。
- 图片以相对路径保存在文档旁边，支持粘贴、拖入和本地选择。
- 深浅主题、专注/只读等显示方式、字数统计、打印，以及 HTML/PDF/Word 导出。
- 编码识别、会话恢复、文件外部改动提示、输入法适配和键盘导航。

这些能力已覆盖多数 Markdown 写作者的基础需求。应优先检查功能是否容易找到、行为是否符合预期、Markdown 是否能完整往返，而不是以功能数量作为产品进度。

## 3. 优先改进项

### P0：先保护文稿，不让保存路径丢内容

| 问题 | 代码依据与用户影响 | 建议 |
|---|---|---|
| 关闭标签时磁盘保存未等待 | `apps/desktop/src/renderer/hooks/useTabs.ts` 的 `closeTab` 对已有路径且 dirty 的标签调用 `void window.api.writeFile(...)`，随后立即移除标签；写入失败没有提示，写盘尚未完成时应用退出也可能丢改动 | 关闭标签前等待保存完成；成功才关闭；失败时保留标签和 dirty 状态，提示“重试 / 取消关闭”。不要用未处理的后台写入承担当次关闭的最后保存 |
| 关闭窗口依赖固定等待时间 | `apps/desktop/src/main/window.ts` 在关闭前发送 flush 请求后固定等待约 120ms，没有等待渲染层保存结果或失败结果 | 建立带 request id 的确认/回复通道：所有有路径的 dirty 标签保存完毕并成功才允许退出；保存失败时显示路径与原因并允许取消退出。关闭时不应因时间到了就假定写盘完成 |
| 外部改动与本地改动冲突时无法恢复 | `App.tsx` 检测到外部改动且本地 dirty 时只显示通知；自动保存仍可能覆盖磁盘上的新版本 | 写入前比较磁盘版本标记（修改时间/大小/摘要），发现磁盘版本已变化时暂停自动保存，提供“查看差异 / 使用磁盘版本 / 保留本地版本另存为”等选择。至少先做到阻止静默覆盖 |
| 写盘不是原子替换 | `apps/desktop/src/main/ipc.ts` 的文件写入直接 `writeFile(path, ...)`，进程崩溃或系统中断可能留下被截断的文件 | 采用同目录临时文件写完后替换目标文件的安全写入流程，并兼容 Windows 替换语义；必要时提供可选的上一次保存副本。保存状态只在替换成功后更新 |
| 自动保存失败对用户不可见 | 自动保存错误被 `catch(() => {})` 吞掉；虽然 dirty 状态仍保留，但用户可能只看到圆点，不知道文件持续写入失败 | 错误时在状态栏显示“未能保存”与原因/重试入口；避免每次按键重复弹窗，可合并同一路径错误并在成功后提示恢复 |

### P1：让常用写作路径更清楚

1. **减少主界面的常驻操作。** 目前原生菜单、底部工具栏、斜杠菜单和快捷键存在多套入口。主工具栏保留约 6–8 个最高频操作（段落/标题、粗斜体、链接、列表、图片、表格、撤销重做）；公式、警告框、脚注、目录、Front Matter、图表等低频项放在斜杠菜单或对应菜单分组。保持入口一致，但不让所有功能都挤在编辑器旁边。
2. **新建文档默认空白。** `useTabs.ts` 中 `DEFAULT_DOC` 当前打开的是带项目介绍的示例文章。首次启动可选“空白文档”作为默认，并将示例作为可选模板，避免用户把示例误当自己的文稿或先花时间清空内容。
3. **明确保存状态。** 标签圆点之外，在当前文档状态区明确显示“正在保存 / 已保存 / 保存失败 / 外部版本已变化”；自动保存不能让用户误以为重要内容已可靠落盘。
4. **多标签可辨认。** 同名文档可能来自不同目录。标签 hover 已带路径，但同时打开多个同名文件时，提供完整路径提示或轻量父目录副标题，避免用户改错文档。
5. **首次使用引导只讲三件事。** 首次打开给出“新建文档、打开文件/文件夹、常用快捷键”简短提示；不要用长功能清单挡住编辑区。README 同样应先给快速开始和核心流程，高级功能放到后续章节。
6. **统一命令入口与发现方式。** 将常用快捷键显示在菜单/提示中；斜杠菜单支持键盘筛选与方向键操作；工具栏图标有清楚的辅助名称。避免为同一动作提供含义不同的多个入口。

### P1：把 Markdown 保真作为产品核心指标

所见即所得编辑器最重要的承诺是：写作简单，保存出的 Markdown 可移植、可预测。建议建立一份“支持语法与往返行为表”，按常见程度验收：

- 标题、段落、换行、粗体/斜体/删除线、行内代码和代码围栏。
- 有序/无序/嵌套/任务列表、引用、分隔线、表格。
- 普通链接、图片相对路径、链接引用、脚注（如保留该能力）。
- YAML Front Matter、数学公式、图表和提示块等扩展语法。

每种语法至少定义：打开后如何显示、编辑后源码是否变化、切换两种模式是否保真、复制/导出行为、未知语法怎样处理。无法编辑的扩展语法应尽量保留原文，不能悄悄删除或改写。

特别建议将“常用 Markdown 文件无意改写”作为发布门槛：打开文件不应仅因解析或自动补充编辑器结构而变 dirty；不编辑就保存不应产生无关格式变化；编辑局部内容不应重排整篇或丢失不支持的语法。

### P2：内容导航与资源管理

- **搜索结果更可控：**文件夹搜索目前有目录、文件数、文件体积及返回结果上限。达到上限时应清楚说明扫描范围、是否有后续结果，并允许缩小目录；搜索中应能取消，避免大目录扫描占用主进程。
- **链接和图片健康检查：**提供可选的文档检查，指出失效的相对图片、缺失文件和空链接；定位到源码行并给出修复路径。先做诊断，不自动改写用户文档。
- **预览与导出检查：**导出前提供轻量预览或打开导出结果；错误时明确指出公式、图片或图表未能渲染的位置。导出文件应保持离线可读，资源引用的处理规则清楚。
- **大文档体验：**以真实长文档检查打开时间、输入延迟、搜索和大纲更新。已有文件大小限制不等于大文档不卡顿；按关键路径量化后再决定是否延迟加载图表/公式或减少重复解析。

## 4. 功能分层：核心保留，低频能力收纳

| 层级 | 建议内容 | 原则 |
|---|---|---|
| 每天都用 | 新建/打开/保存、撤销重做、标题和段落、粗斜体、列表、引用、代码、链接、图片、表格、查找、文档导航 | 一眼能找到，常见动作不超过一两步 |
| 需要时用 | 文件夹搜索、源码模式、公式、图表、任务列表、Front Matter、提示块、导出、打印、只读/专注模式 | 可通过斜杠菜单、命令搜索或分组菜单进入，不挤占正文空间 |
| 先不扩张 | 云同步、账号、多人协作、AI 生成/改写、插件市场、复杂模板商城、项目管理面板 | 这些会改变纯本地写作工具的定位，也会增加设置、维护和信任成本 |

高级能力已实现的不必删除；优先通过渐进展示降低视觉复杂度。若用户反馈某个高级能力确实高频，再考虑提升入口层级。

## 5. 建议实施顺序

### 阶段一：数据安全

- 关闭标签等待写盘结果，失败时不关闭。
- 关闭窗口采用明确的保存确认/失败回复，不再靠固定延时。
- 自动保存失败可见；外部文件变化时阻止静默覆盖。
- 文件保存改为原子替换，并覆盖“保存失败、退出、磁盘文件被外部改动”的场景。

### 阶段二：简化写作界面

- 新建文档默认空白，示例改为可选。
- 主工具栏收敛到日常高频动作，高级排版通过斜杠菜单/菜单访问。
- 对标签标题、保存状态、外部冲突、空状态和快捷键提示统一信息表达。

### 阶段三：Markdown 保真与核心质量

- 建立常用语法矩阵及 round-trip 测试样例。
- 检查中英文输入法、粘贴、列表续写、表格增删、链接图片相对路径、源码/渲染切换。
- 用真实长文档测量打开、输入、搜索和导出表现。

### 阶段四：按反馈补充导航与资源检查

- 为大目录搜索补充取消、范围说明与结果分页/缩小范围。
- 增加失效链接/图片的只读检查。
- 根据真实使用反馈决定是否增加预览、模板或批量整理能力。

## 6. 工程审查提醒

- 若干核心文件超过项目约定的 500 行：`packages/editor/src/slash.ts`、`packages/editor/src/instance.ts`、`apps/desktop/src/main/ipc.ts`、`apps/desktop/src/renderer/App.tsx`、`apps/desktop/src/renderer/hooks/useTabs.ts`。建议按菜单/命令、文件操作、文档状态、渲染与布局职责逐步拆分；优先在阶段一之后做，避免边改核心保存逻辑边大规模搬代码。
- 应用主进程拥有文件系统能力，Preload 暴露了读写、目录、搜索和系统操作接口。继续保持 API 最小化，并在主进程验证 IPC 入参、调用来源和允许的协议；`setWindowOpenHandler` 也应沿用外链协议白名单，避免绕过统一校验。
- 维护一套跨平台回归矩阵，重点覆盖 macOS/Windows 的快捷键、输入法、文件重命名/占用、路径分隔符和原子替换语义。当前已有较丰富的单元、菜单和 Electron E2E 覆盖，新增检查应优先针对文稿安全和 Markdown 往返，而非继续只扩菜单断言。
- 设计规范和协作约定都强调简洁与克制；落地时先核对文字工作者的常见任务，不为满足“功能看起来丰富”而增加低频按钮。

## 7. 验收基线

完成首轮改进后，应能确认：

1. 保存失败不会关闭或清除唯一一份编辑内容，用户能看到原因并重试。
2. 磁盘文档在编辑器外发生变化时，不会被自动保存静默覆盖。
3. 退出等待真实保存结果；超过合理时限或保存失败时，用户可取消退出。
4. 高频写作任务不需要学习完整菜单：新建、排版、插链接/图片/表格、查找、定位、保存均可直接完成。
5. 常见 Markdown 打开、轻微编辑、切换模式和保存后结构保持稳定；不支持的扩展不被静默丢弃。
6. 高级功能仍可访问，但默认编辑界面的主次清楚、没有重复按钮堆叠。
