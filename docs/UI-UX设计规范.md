# ai-md-editor UI/UX 设计规范

> 视觉方向：现代极简（Linear / Raycast / Vercel 气质）｜ 动效：CSS 过渡（克制使用）
>
> 版本：v1.0 ｜ 日期：2026-10-25
>
> 方法论来源：emilkowalski/skills（动画与交互的正确决策）+ taste-skill（设计品味与去 AI 味）

---

## 0. 本规范怎么用

这份规范解决一个核心问题：**如何让一个桌面 Markdown 编辑器看起来、动起来像「人做的高质量产品」，而不是「AI 生成的默认界面」。**

它把两套网页方法论**适配**到了桌面编辑器场景。桌面编辑器与网页的关键差异：

| 维度 | 网页（两套 skill 的原生场景） | 桌面编辑器（本项目） |
|------|------|------|
| 使用频率 | 偶尔访问，追求「惊艳」 | **每天高频使用**，追求「专注与顺手」 |
| 动效基调 | 可以有愉悦感 | **克制动效**——高频交互几乎不动画 |
| 核心区域 | 营销、叙事、滚动 | **编辑区是绝对主角**，一切 UI 为其让路 |
| 色彩 | 品牌色、色场 | **色彩花在内容上**（语法高亮、状态），而非装饰 |

因此：**网页 skill 里「惊艳、个性、art direction」的规则要弱化，「克制、专注、动效正确性」的规则要强化。**

## 1. 设计原则（5 条）

1. **内容优先（Content First）**：编辑区是唯一的主角。所有 chrome（工具栏、侧边栏、状态栏）都要「退后」，让用户的注意力留在文字上。底部工具栏固定占位、按钮较多时允许换行但不覆盖正文；同一能力只留一个入口——代码用唯一的「代码块」按钮，段落下拉只放正文与标题，不再塞重复的引用/代码块；链接表单锚在触发按钮上方，与快速插入菜单共用同一套字段样式，不额外造一层界面语言。插入类片段（警告框）必须让用户插完就能直接打字，不要把语法标记留在光标前；分区线是「线」，左右两段必须落在同一水平线上，靠共用底栏高度而不是各自 padding 去凑。
2. **克制动效（Restrained Motion）**：每天用上百次的操作（输入、光标移动、快捷键）**零动效**；偶尔的操作（打开面板、切换主题）用短促、正确缓动的动效。
3. **安静优先（Quiet over Loud）**：默认态安静（细边框、灰阶、无阴影），只有真正「浮起」的东西（菜单、对话框、命令面板）才有阴影和层级感。
4. **色彩花在内容上（Color for Content）**：界面本身近中性，颜色只出现在语法高亮、链接、选中态、以及需要警示的状态上。
5. **一致性即品质（Coherence）**：缓动曲线、时长、间距、圆角、字阶全系统统一，不出现「某个角落用了另一种风格」。

## 2. 去 AI 味检查清单（核心）

> 这是本规范最需要被「严格执行」的部分。每一条都来自对「AI 生成默认界面」的逆向——那些「挑不出错、但没有任何决定」的样式。

### 2.1 禁止清单（硬规则，触发即改）

| ❌ 禁止 | ✅ 替代 | 说明 |
|------|------|------|
| 图标顶置的「功能卡片」成排排列 | 真实的工具按钮、列表、表格 | AI 落地页的招牌动作 |
| 标题上方的小标签 / 药丸徽章 / "New" chip | 信息直接放进标题或省略 | 「eyebrow」是最大 AI 味信号 |
| 柔和渐变背景、渐变按钮、渐变文字 | 平色（solid）；内容区纯白/纯浅色 | 编辑器尤其要平色，避免视觉噪声 |
| 静止元素的阴影 / 发光 | 表面之间用「色调台阶」（不同灰阶区分层级） | 只有浮起物才有阴影 |
| 细发丝分割线堆砌、1px 描边盒子 | 用间距、背景色阶、字号变化分区 | 线越多越「模板」 |
| 等宽字体用在非代码处 | 正文字体；数字对齐用 `font-variant-numeric: tabular-nums` | 等宽只留给代码块 |
| 01/02/03 序号、"Step 2" 式编号 | 位置、字号、`<ol>` 表达顺序 | 界面里序号很「说明书」 |
| 小号大写字母间距标签（letter-spaced small caps） | 句子大小写、可读字号 | 装饰性追踪大写是重灾区 |
| 标题中「风格化强调词」（彩色/斜体/衬线混排） | 一种字体、一种颜色 | 强调靠内容本身 |
| 超过 2 种字体 | 1 种无衬线 + 1 种等宽（代码） | 极简 = 字体制约 |
| 灰条假仪表盘、装饰形状、渐变 blob、emoji | 真实界面片段，或什么都不放 | 空着比塞假内容好 |
| `transition: all 300ms` | `transition: transform 160ms ease-out` | 精确属性，不用 `all` |
| 该用 ease-out 用 ease-in | 一律 ease-out / 自定义曲线 | ease-in 起始慢，显得迟钝 |
| 从 `scale(0)` 入场 | `scale(0.95)` + `opacity: 0` | 现实没有从无到有 |

### 2.2 「去除装饰后」的另一半——实质（Substance）

> taste-skill 的关键洞察：拿掉装饰只完成一半，什么都没补上的界面读起来**单薄**。编辑器里「补实质」的方式：

- **尺度（Scale）**：把主要的东西做大——编辑区的正文足够大、可读，标题层级靠字号拉开，而不是靠线。
- **留白（Whitespace）**：用留白建立层级，而不是用框线。留白是编辑器的「呼吸感」。
- **完整内容（Real Content）**：默认打开、预览、示例文档用**真实内容**，绝不用 lorem。
- **真实的数据/状态**：状态栏显示真实的字数、行数、光标位置、文件路径，而不是占位符。

### 2.3 每天高频操作的动效铁律

> 这是 emilkowalski 最核心的一条，对编辑器尤其致命。

| 频率 | 操作 | 动效决策 |
|------|------|----------|
| 每天 100+ 次 | 输入、光标移动、语法即时渲染、快捷键 | **零动效** |
| 每天数十次 | 悬停反馈、标签切换、列表导航 | 极短（≤150ms）或不做 |
| 偶尔 | 打开命令面板、设置面板、抽屉 | 标准动效（150–250ms，ease-out） |
| 罕见 | 首次启动引导、主题切换的全屏过渡 | 可以有愉悦感（但主题切换也要快） |

**关键结论：WYSIWYG 的「输入即渲染」本身绝不能带过渡动画**——它必须是即时的。任何在输入和渲染之间插入的动画，都会破坏「所见即所得」的核心体验。

## 3. 视觉规范（Design Tokens）

### 3.1 配色（现代极简 · 中性为主）

采用「中性界面 + 少量强调色」策略。色彩花在内容（语法高亮、链接、状态）上。

**Light 主题（默认）：**

| Token | 值 | 用途 |
|------|-----|------|
| `--bg-app` | `#fafafa` | 应用最外层背景（窗口 chrome 区） |
| `--bg-panel` | `#ffffff` | 编辑区、面板背景 |
| `--bg-subtle` | `#f5f5f5` | 侧边栏 hover、代码块背景、选中态 |
| `--bg-hover` | `rgba(0,0,0,0.04)` | 悬停反馈 |
| `--border` | `#e5e5e5` | 安静边框 |
| `--border-subtle` | `#ededed` | 更弱的边框/分隔 |
| `--text-primary` | `#1a1a1a` | 正文（墨色） |
| `--text-secondary` | `#666666` | 次要文字 |
| `--text-tertiary` | `#999999` | 辅助、占位符 |
| `--accent` | `#2563eb` | 强调色（选中、链接、焦点） |
| `--accent-subtle` | `rgba(37,99,235,0.1)` | 强调色浅底 |

**Dark 主题（对称结构，值反转）：**

| Token | 值 |
|------|-----|
| `--bg-app` | `#111111` |
| `--bg-panel` | `#1a1a1a` |
| `--bg-subtle` | `#222222` |
| `--bg-hover` | `rgba(255,255,255,0.06)` |
| `--border` | `#2a2a2a` |
| `--text-primary` | `#e5e5e5` |
| `--text-secondary` | `#9a9a9a` |
| `--text-tertiary` | `#666666` |

> 强调色在深色主题下可略调亮（`#3b82f6`），保证对比度。

**语法高亮配色**：单独一套，遵循「柔和、低饱和、可读」原则，具体在编辑器中用 Shiki 的主题（如 `github-light` / `github-dark`）适配，不做霓虹高亮。

### 3.2 字体

| 用途 | macOS | Windows | Fallback |
|------|-------|---------|----------|
| 正文 UI / 编辑 | `-apple-system` (SF Pro) | `Segoe UI` | `PingFang SC` / `Microsoft YaHei` |
| 代码 / 等宽 | `SF Mono` | `Cascadia Code` | `Menlo` / `Consolas` |

**规则：**
- 全局只用 1 套无衬线（系统字体）+ 1 套等宽（代码），不引入第三套
- 正文基准字号 `--font-size-base: 16px`（编辑器正文 16px 起，保证中文可读性）
- 数字对齐用 `font-variant-numeric: tabular-nums`（行号、字数统计、表格数字）

### 3.3 间距与圆角

| Token | 值 | 用途 |
|------|-----|------|
| `--space-1` | 4px | 微间距 |
| `--space-2` | 8px | 紧凑间距 |
| `--space-3` | 12px | 常规间距 |
| `--space-4` | 16px | 区块间距 |
| `--space-6` | 24px | 大区块间距 |
| `--radius-sm` | 4px | 小控件 |
| `--radius-md` | 6px | 按钮、输入框 |
| `--radius-lg` | 8px | 面板、弹层 |

**规则：**
- 圆角统一小圆角（4–8px），**不用大圆角/胶囊**（胶囊是 AI 味的重灾区）
- 层级用「间距 + 背景色阶」表达，不用「框线 + 阴影」堆砌

## 4. 动效规范

> 采用 **Motion (Framer Motion)**。核心规则直接来自 emilkowalski 的方法论。

### 4.1 缓动曲线（自定义，不用内置）

```css
/* UI 交互的强力 ease-out */
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);
/* 屏幕内移动的 ease-in-out */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
```

**绝对禁止 UI 用 `ease-in`**（起始慢，显得迟钝）。

### 4.2 时长（铁律：UI 动画 < 300ms）

| 元素 | 时长 | 缓动 |
|------|------|------|
| 按钮按下反馈 | 100–160ms | ease-out |
| 悬停反馈、tooltip | 125–200ms | ease-out |
| 命令面板、下拉 | 150–250ms | ease-out |
| 设置面板、抽屉 | 200–500ms | ease-in-out / ease-drawer |
| 主题切换 | 200–300ms | ease-out |

### 4.3 可动画属性（性能铁律）

- **只动画 `transform` 和 `opacity`**（GPU 合成，跳过布局/绘制）
- 禁止动画 `width` / `height` / `padding` / `margin`
- Motion 中用 `transform` 字符串而非 `x`/`y` 简写（前者硬件加速）

```tsx
// ✅ 硬件加速
<motion.div animate={{ transform: "translateX(100px)" }} />
// ❌ 主线程 rAF，负载下掉帧
<motion.div animate={{ x: 100 }} />
```

### 4.4 交互细节（正确性清单）

| 场景 | 正确做法 |
|------|----------|
| 按钮按下 | `:active { transform: scale(0.97) }`，160ms |
| 弹层入场 | 从 `scale(0.95) + opacity 0` 起，`transform-origin` 锚定触发源（模态框例外，居中） |
| 列表入场 | 交错延迟 30–80ms（仅装饰，不阻塞） |
| 触屏 | hover 动画用 `@media (hover:hover) and (pointer:fine)` 门控 |
| 无障碍 | `prefers-reduced-motion` 时只保留透明度/颜色过渡，去掉位移 |
| 可中断 | 动态 UI 用 transition 而非 keyframes（keyframes 中断会从零重启） |

### 4.5 编辑器的动效「白名单」

这是本项目最关键的动效决策，明确「哪里动、哪里不动」：

| 交互 | 动效 |
|------|------|
| 输入、光标、语法渲染 | ❌ 零动效（WYSIWYG 核心） |
| 悬停（工具栏图标、侧边栏项） | 背景色阶过渡 150ms |
| 命令面板（Cmd/Ctrl+P） | 打开 scale(0.98→1) + fade，180ms ease-out |
| 设置/抽屉面板 | 滑入 250ms ease-drawer |
| 主题切换 | 全屏 fade 200ms（快，不炫） |
| 大纲树折叠 | 高度过渡（或用 transform，200ms） |
| 状态栏提示 | fade 150ms |

## 5. 布局规范（编辑器整体架构）

### 5.1 整体布局

```
┌─────────────────────────────────────────────────────┐
│  顶部栏（可选，极简：标题 + 少量操作）                    │
├──────────┬──────────────────────────┬───────────────┤
│          │                          │               │
│  侧边栏   │       编辑区（主角）        │   大纲/预览    │
│ (文件树/  │     WYSIWYG 渲染           │  (可折叠)      │
│  大纲)    │                          │               │
│          │                          │               │
├──────────┴──────────────────────────┴───────────────┤
│  状态栏（字数/行数/光标位置/文件路径）                    │
└─────────────────────────────────────────────────────┘
```

### 5.2 布局原则

- **编辑区绝对主角**：默认不显示顶部栏和侧边栏（或侧边栏默认折叠），给编辑区最大空间。沉浸式写作正是这类工具的核心魅力。
- **内容列宽受限**：编辑正文最大宽度约 `720px` 居中，两侧留白，避免长行阅读疲劳。
- **对称与留白**：编辑区左右留白对称；侧边栏打开时不挤压正文到变形。
- **状态栏安静**：细边框之上、极简一行，信息用 `--text-tertiary` 色，不抢眼。

### 5.3 各区域设计要点

| 区域 | 设计要点 |
|------|----------|
| **编辑区** | 纯白/纯色背景，无边框无阴影；正文 16px；行高 1.6–1.7；WYSIWYG 即时渲染 |
| **侧边栏** | 可折叠；文件树/大纲；hover 用 `--bg-hover`；选中态用 `--bg-subtle` |
| **大纲** | 从标题 AST 生成；层级缩进；点击跳转；当前标题高亮；可拖动标题整节重排，落点用 2px 插入指示线、被拖条目半透明，不新增按钮或拖拽手柄 |
| **状态栏** | 一行；左：文件路径/状态；右：行号、字数、光标列 |
| **命令面板** | Cmd/Ctrl+P 唤起；居中浮层；模糊背景（仅此一处可用 backdrop blur，因为它是真正浮起的） |

## 6. 组件规范

### 6.1 按钮

- 默认「幽灵按钮」（text-only，hover 显示 `--bg-hover`），避免满屏实心按钮
- 主操作按钮才用实心 `--accent` 背景
- 按下反馈 `scale(0.97)` 160ms
- 图标按钮 hover 出 tooltip

### 6.2 输入框 / 搜索

- 细边框 `--border`，聚焦时边框变 `--accent`（不放大、不发光）
- 圆角 `--radius-md`（6px）

### 6.3 弹层 / 面板

- 真正浮起 → 允许阴影（但柔和、低透明度）
- 命令面板可用 backdrop-blur（唯一例外）
- `transform-origin` 锚定触发源

### 6.4 菜单 / 下拉

- 150–250ms ease-out
- 悬停项背景 `--bg-hover`，不用边框分隔

### 6.5 表格 / 数据

- 数字 `tabular-nums` 对齐
- 用背景色阶斑马纹，不用密集边框线

## 7. 编辑器 WYSIWYG 交互规范

> 这是本项目区别于普通网页的「核心交互」，单独规范。

### 7.1 语法符号的显隐

- 光标不在该行 → 语法符号隐藏，只显示渲染结果
- 光标移入该行 → 语法符号淡入（**无位移动画**，纯 opacity 或直接显示）

### 7.2 光标与焦点

- 光标样式、选区颜色用 `--accent`，但**不动画**
- 焦点态用安静的方式表达（如选中文本背景色）

### 7.3 中文输入法（IME）

- 组合输入期间，暂停所有 Markdown 自动转换
- 组合期间的视觉状态不闪烁、不重排

### 7.4 代码块

- 等宽字体、`--bg-subtle` 背景、语言标签
- 语法高亮柔和，不做霓虹

## 8. 检查清单（交付前逐项核对）

### 8.1 去 AI 味（对照 §2.1 禁止清单）

- [ ] 无功能卡片、无 eyebrow 徽章、无渐变、无静止阴影/发光
- [ ] 无细发丝线堆砌、无序号编号、无小号大写追踪标签
- [ ] 无风格化强调词、≤2 种字体、等宽只用于代码
- [ ] 无灰条假内容，全部真实数据/状态

### 8.2 动效正确性（对照 §4）

- [ ] 高频操作零动效；低频操作时长 < 300ms
- [ ] 无 `ease-in`；使用自定义 cubic-bezier
- [ ] 只动画 transform/opacity；Motion 用 transform 字符串
- [ ] 按钮有 `:active` 反馈；触屏有 media query 门控
- [ ] 有 `prefers-reduced-motion` 降级

### 8.3 布局与内容（对照 §5、§1）

- [ ] 编辑区是主角，chrome 退后；正文列宽 ≤720px 居中
- [ ] 左右留白对称；无挤在一侧的 section；无空白拉伸
- [ ] 侧栏底栏与编辑区工具栏的顶部分区线严格对齐；竖线在交点处贯通，无台阶或断口
- [ ] 状态栏安静、信息真实；主题切换流畅
- [ ] 数字 tabular-nums 对齐；正文 16px 起
- [ ] 警告框等带语法标记的片段插入后可直接输入，标记不外露成正文

### 8.4 分发界面（安装镜像，对照技术方案 §10.5）
